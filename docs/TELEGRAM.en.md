# Configuration Guide: Telegram Bot Notifications

> 🌐 **Languages:** [Português](TELEGRAM.md) | English

This guide explains how to configure automatic Telegram notifications for the
**AliExpress Coin Collector & Task Runner**. The Portuguese version is canonical; if they
diverge, [TELEGRAM.md](TELEGRAM.md) prevails.

The feature is **100% optional** (disabled by default) and uses Node.js 22's native HTTP
client (`fetch`), with no additional external library.

---

## 📋 Notification Features

- **Automatic Real-Time Status:** Notifies successful runs (+ coins), already-collected
  runs, critical failures and active-lockfile alerts.
- **Rich HTML Formatting:** Shows updated balance, day streak, coins earned, completed
  tasks and execution time.
- **Resilient & Non-Blocking:** If the Telegram API is slow or unavailable, automation
  logs a warning and preserves the job's original exit code (it never aborts the script).
- **Multi-Account Support:** Groups and consolidates all account statuses into one elegant
  message. With `TELEGRAM_PER_ACCOUNT=true`, it also sends each account's individual
  detail.
- **Silent Mode:** Optional send without sound (`TELEGRAM_SILENT=true`), ideal for
  overnight Cron runs.

## 🤖 Step 1: Create the Bot on Telegram with @BotFather

1. In your Telegram app (mobile or desktop), search for **`@BotFather`** (check the blue
   verified badge) or open [t.me/BotFather](https://t.me/BotFather).
2. Send `/start` and then:
   ```text
   /newbot
   ```
3. BotFather will ask for a display **name** for the bot (example: `Ali Coins Notifier`):
   ```text
   Alright, a new bot. How are we going to call it? Please choose a name for your bot.
   > Ali Coins Notifier
   ```
4. Now provide a unique **username**, which must end in `bot` (example: `my_alicoins_bot`):
   ```text
   Good. Now let's choose a username for your bot. It must end in `bot`. Like this, for example: TetrisBot or tetris_bot.
   > my_alicoins_bot
   ```
5. BotFather will reply with a confirmation containing your **HTTP API Token**:
   ```text
   Done! Congratulations on your new bot.
   Use this token to access the HTTP API:
   <BOT_TOKEN>

   Keep your token secure and store it safely, it can be used by anyone to control your bot.
   ```
6. **Copy and store this token.** It will be your `TELEGRAM_BOT_TOKEN`.
7. Also keep the permanent direct link to your bot generated by @BotFather (example:
   `t.me/my_alicoins_bot`).

## 💬 Step 2: Initialize the Conversation with the Bot (Prior Authorization Required)

> [!IMPORTANT]
> **Telegram Bot API architectural restriction:** Due to Telegram's strict privacy and
> anti-spam policies, **bots cannot initiate conversations with users**. An application has
> no technical permission to send messages to a recipient who has never interacted with the
> bot. If a send is attempted without prior authorization, the Telegram API rejects it
> with `HTTP 403: Forbidden: bot can't initiate conversation with a user` or
> `HTTP 400: Bad Request: chat not found`.

Before obtaining your identifier or filling in the system settings, you must authorize the
bot through first contact:

1. In the Telegram app, open the conversation with your newly created bot by searching for
   the **username** defined in Step 1 (example: `@my_alicoins_bot`) or by opening the
   permanent link provided by `@BotFather` (`https://t.me/my_alicoins_bot`).
2. In the conversation window, click **Start** (or send `/start` manually).
3. With that initial command, the communication channel is formally open and the bot is
   fully authorized to send notifications and execution reports to your account.

---

## 🆔 Step 3: Obtain Your `CHAT_ID`

For the bot to send messages to you, it needs the unique numeric identifier of your chat
(`TELEGRAM_CHAT_ID`).

### Method A: Fastest (via @userinfobot)

1. Search for **`@userinfobot`** on Telegram and send any message or `/start`.
2. The bot replies with your account data. Copy the numeric value of the **`Id`** field
   (example: `987654321` for individual accounts or `-100...` for channels/groups).

### Method B: Native Telegram API

Since you already started the conversation with your bot in **Step 2**, the chat data is
registered on Telegram's servers:

1. In your terminal, run `curl`, replacing `YOUR_TOKEN` with the token from Step 1:
   ```bash
   curl -s "https://api.telegram.org/botYOUR_TOKEN/getUpdates"
   ```
2. In the returned JSON, find the `"chat":{"id": 987654321, ...}` property. That number is
   your `TELEGRAM_CHAT_ID`.

## ⚙️ Step 4: Configure `credentials.env`

Open `credentials.env` and fill in the corresponding variables:

```env
# Enable notification sending
TELEGRAM_ENABLED=true

# Token provided by @BotFather (format: numbers:characters)
TELEGRAM_BOT_TOKEN="<BOT_TOKEN>"

# Your user ID or group/channel ID
TELEGRAM_CHAT_ID="987654321"

# Specific chat IDs for secondary accounts (optional):
# If omitted, all accounts inherit and notify automatically on the main TELEGRAM_CHAT_ID:
# TELEGRAM_CHAT_ID_2="111222333"
# TELEGRAM_CHAT_ID_3="444555666"

# Also send each account's INDIVIDUAL notification, in addition to the consolidated one
# (default: false). With false, accounts using the same chat as the consolidated one have
# their individual message suppressed (avoids bursts); the consolidated one is always sent.
TELEGRAM_PER_ACCOUNT=false

# Send a silent notification (no sound) (default: false)
TELEGRAM_SILENT=false

# HTTP timeout in milliseconds for the Telegram API request (default: 5000)
TELEGRAM_TIMEOUT_MS=5000

# Custom host label in messages (optional, useful for Docker/VPS)
NOTIFY_HOST_LABEL="my-vps-server"
```

> 💡 **Multi-account with only 1 bot / 1 chat (recommended):**
> If you want all account reports in the same bot and conversation, declare only
> `TELEGRAM_CHAT_ID`. The system automatically falls back to all accounts and sends the
> **consolidated summary** to the same chat. To avoid message bursts, each account's
> **individual** notification is suppressed when its chat equals `TELEGRAM_CHAT_ID`
> (default behavior, `TELEGRAM_PER_ACCOUNT=false`). Enable `TELEGRAM_PER_ACCOUNT=true` to
> also receive each account's detail separately (e.g. with dedicated
> `TELEGRAM_CHAT_ID_2`/`TELEGRAM_CHAT_ID_3`).

Ensure the file permissions are restricted to your user:

```bash
chmod 0600 credentials.env
```

## 📊 Notified Events and Formatting

| Event                      | Exit Code | Notification Sent | Content Example                                                                |
| :------------------------- | :-------: | :---------------: | :----------------------------------------------------------------------------- |
| **Success**                |    `0`    |        Yes        | Final balance, coins earned today, day streak and completed task list          |
| **Already Collected**      |    `2`    |        Yes        | Reports that coins were already collected and no tasks are pending             |
| **Critical Failure**       |    `1`    |        Yes        | Error details (expired login, network timeout or inaccessible selector)        |
| **Active Lock**            |    `3`    |        Yes        | Overlap alert (another instance is already running on the host)                |
| **Broken Streak**          |    `4`    |        Yes        | 🚨 Critical streak-break alert (yesterday → today + current balance)           |
| **2FA Required (Cron)**    |    `5`    |        Yes        | 🔐 Fast interruption (<5s) in cron without TTY with export/import instructions |
| **Global Failure (Crash)** |    `6`    |        Yes        | 💥 Unhandled fatal error or rejected Promise (uncaughtException / unhandled)   |

### Example Received Message (Individual Notification per Account):

Sent in single-account mode and, in multi-account mode, only with
`TELEGRAM_PER_ACCOUNT=true` (with the default `false`, the individual one is suppressed
when the chat matches the consolidated one).

```text
✅ ali-coins — 2026-09-22
👤 Account: jo***@example.com
🖥️ Host: vps-server (v1.6.0)
🪙 Earned today: +111 coins (check-in +40 / tasks +71)
📅 Streak: 219 days
💰 Balance: 3043 coins
⏱️ Duration: 2m 27s
```

> With no new action (check-in already collected and no pending tasks), the title becomes
> `ℹ️ ali-coins — ...` and earnings show as `+0`.

### Example Received Message (Multi-Account Consolidated):

Always sent in multi-account mode (regardless of `TELEGRAM_PER_ACCOUNT`):

```text
✅ AliExpress Coins - Multi-Account (Success) — 2026-09-22
📊 Summary: 2/2 accounts processed successfully

[1] jo***@example.com: 💰 3043 coins | 🪙 +111 (+40/+71) | Streak: 219
[2] ma***@example.com: 💰 625 coins | 🪙 +57 (+1/+56) | Streak: 7

⏱️ Total Duration: 5m 10s
📅 Date: 2026-09-22 15:28:28
🖥️ Host: vps-server (v1.6.0)
```

> With no new action, the title becomes `ℹ️ ... (Already Collected)`. If any account
> fails, the consolidated message is sent in failure format (🔴) with the **list of
> affected accounts** (including each account's real error):

```text
🔴 AliExpress Coins - Multi-Account (Failure) — 2026-09-23
📊 Summary: 1/2 accounts processed successfully

[1] jo***@example.com: 💰 3043 coins | 🪙 +0 (+0/+0) | Streak: 219
[2] ma***@example.com: ❌ Failure (Error logging in: unable to obtain streak and balance for account "ma***@example.com".)

⏱️ Total Duration: 3m 53s

⚠️ Remote Session Warning:
One or more accounts use a session imported from another host that appears to have expired.
💡 Action required: Generate a new session with node export_session.js on the source server and import it with node import_session.js.
📅 Date: 2026-09-23 17:57:04
🖥️ Host: vps-server (v1.6.0)
```

### Example Received Message (Failure with Expired Imported Session):

```text
🔴 ali-coins — 2026-09-22 15:23:38
⚠️ Error: Error logging in: unable to obtain streak and balance for account "fe***@example.com".
👤 Account: fe***@example.com
🖥️ Host: vps-server (v1.6.0)

⚠️ Remote Session Warning:
The session in use was imported from another host (via import_session.js) and appears to have expired or been invalidated by AliExpress.
💡 Action required: Generate a new session by running node export_session.js on the source server and import it on this host with node import_session.js.
```

## 🚩 Command-Line Parameters (CLI)

You can control notification sending directly when running any command:

- **`--notify`**: Forces notifications on, even if `TELEGRAM_ENABLED=false` in
  `credentials.env`:
  ```bash
  npm start -- --notify
  ```
- **`--no-notify`**: Disables notifications for that specific run, even if they are
  enabled in `credentials.env`:
  ```bash
  npm start -- --no-notify
  ```

### Cron Scheduling and Periodic Rotation

When scheduling automated tasks on the server via `crontab`, you can freely switch the
sending behavior:

- **Normal Daily Run (with Telegram):**
  ```bash
  15 4 * * * cd /home/ubuntu/ali-coins && /usr/bin/node all.js >> /home/ubuntu/ali-coins/cron.log 2>&1
  ```
- **Silent Daily Run (no Telegram alerts):**
  ```bash
  15 4 * * * cd /home/ubuntu/ali-coins && /usr/bin/node all.js --no-notify >> /home/ubuntu/ali-coins/cron.log 2>&1
  ```
- **Monthly At-Rest Key Rotation (`--rotate`):**
  ```bash
  # Rotation on day 1 of each month at 03:00 with backup in scratch/ and automatic 7-day pruning
  0 3 1 * * cd /home/ubuntu/ali-coins && /usr/bin/node export_session.js --rotate --new-secret-from-env=SESSION_SECRET_NEW >> /home/ubuntu/ali-coins/rotation.log 2>&1
  ```

## 🔍 Troubleshooting

### 1. `HTTP 401: Unauthorized`

- **Cause:** The token configured in `TELEGRAM_BOT_TOKEN` is mistyped, has extra spaces or
  was revoked in `@BotFather`.
- **Solution:** Copy the exact token generated by `@BotFather` again.

### 2. `HTTP 403: Forbidden: bot was blocked by the user`

- **Cause:** You blocked the bot in Telegram's chat options or deleted the conversation.
- **Solution:** Open the bot in Telegram, unblock it and click `Restart` or send `/start`.

### 3. `HTTP 400: Bad Request: chat not found` or `HTTP 403: Forbidden: bot can't initiate conversation with a user`

- **Cause:** The provided `TELEGRAM_CHAT_ID` is invalid or the prior conversation
  initialization step was not performed. By Telegram Bot API architecture and privacy
  guidelines, bots cannot initiate conversations with any user; the recipient must send the
  first message.
- **Solution:** Open the conversation with your bot on Telegram (search for your
  `@username` or open `https://t.me/<your_bot_username>`), click **Start** (`/start`) and
  verify that `TELEGRAM_CHAT_ID` in `credentials.env` exactly matches the numeric
  identifier obtained in Step 3.

### 4. Timeout / Network Error

- **Cause:** Your server or VPS blocks outbound traffic to `api.telegram.org` (or
  censorship in countries such as Russia/Iran/China).
- **Solution:** Check connectivity by running `curl -I https://api.telegram.org`. If
  needed, use a proxy or increase the timeout with `TELEGRAM_TIMEOUT_MS=10000`.

### 5. `⚠️ Remote Session Warning` received on Telegram

- **Cause:** Automation is running on a remote server/VPS with a session received from
  another host (`node import_session.js`), and that session expired or was invalidated by
  AliExpress. Because the server is on a datacenter IP, interactive login with
  username/password cannot complete automatically due to anti-bot protections (slider
  captcha or 2FA).
- **Solution:** On the original personal computer (residential IP with an active session):
  ```bash
  node export_session.js
  ```
  Then import the new token on the remote server:
  ```bash
  node import_session.js < session_token.txt
  ```

## 🚦 Exit Codes and Notified Events

The Telegram bot reports the main events associated with the system's exit codes:

|  Code   | Telegram Event           | Description                                                                 |
| :-----: | :----------------------- | :-------------------------------------------------------------------------- |
| **`0`** | `success`                | Run completed successfully and coins were added.                            |
| **`1`** | `failure`                | Critical execution or authentication failure.                               |
| **`2`** | `already_collected`      | Idempotent run: coins already collected and no pending tasks.               |
| **`3`** | `lock_active`            | Run blocked: another active instance on the host.                           |
| **`4`** | `streak_break`           | Critical alert: daily streak interrupted.                                   |
| **`5`** | `2fa_required`           | 2FA requested in a non-interactive environment (cron/CI).                   |
| **`6`** | `failure` (Global Crash) | Emergency notification sent by `uncaughtException` or `unhandledRejection`. |
| **`7`** | `manual_login_required`  | Manual login required (RGV587 gate or unfinished window); no retry.         |

## 🛑 How to Disable

To permanently disable notifications, set this in your `credentials.env`:

```env
TELEGRAM_ENABLED=false
```

Or simply remove/comment the Telegram lines. The script continues working normally without
sending any external request.
